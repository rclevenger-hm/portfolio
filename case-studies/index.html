OCISafe automationPython

OCI Ephemeral Resource Janitor

Destructive automation should earn permission in layers. This project uses explicit ownership, protection tags, dry-run defaults, action caps, fail-closed policy parsing, and a two-phase stop-then-terminate path.

Failure question
How do you keep one bad cleanup assumption from becoming a broad outage?
Evidence
Policy engine, OCI action path, structured reasons, tests, and CI.

AWSAsync processingTerraform

Identity Document Screening Pipeline

A reference pipeline that separates request acceptance from variable-latency processing with durable state, SQS retries, a dead-letter queue, status lookup, retention controls, and narrow execution roles.

Failure question
What stays recoverable when intake, queue handoff, or processing fails independently?
Evidence
Lambda/SQS/DynamoDB/S3 implementation, Terraform, explicit status fields, and failure analysis.

Kafka on OCI

A reliability-oriented Kafka architecture where controller quorum, replication, private networking, capacity headroom, telemetry, and operator procedure are treated as one failure envelope.

Failure question
What still has to be true after losing a broker, controller, disk, network path, or fault domain?
Evidence
Reference topology, capacity model, alerting model, runbook, and failure scenarios.

OCIHadoopSSH

OCI Hadoop Job Automation

A small remote-execution service built around bounded waits, SSH host verification, safe command construction, explicit failure propagation, and one important rule: a timeout is an unknown outcome.

Failure question
When the caller loses visibility, how do you avoid turning uncertainty into duplicate remote work?
Evidence
Request validation, SSH controls, timeout behavior, unit tests, and an operations runbook.

Sports Gamecast

A dependency-light live sports application that consumes an undocumented upstream feed. Reliability comes from defensive parsing, game-state-aware refresh, deterministic browser tests, PWA checks, and deployment gates rather than pretending the upstream interface is stable.

Failure question
How should a static product behave when its live data dependency is useful but not a supported production contract?
Evidence
Browser code, mocked Playwright tests, workflow gates, PWA validation, and generated broadcast-data checks.
